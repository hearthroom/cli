# Plan 09 — Release and distribution

## Goal

Anyone on Linux, macOS or Windows installs `hearthroom` with one command and
never compiles anything. No paid developer accounts are required.

## Channels

| Channel | How | Status for v0.1 |
|---|---|---|
| GitHub Releases | GoReleaser on tag `v*`; archives + `checksums.txt` | ships |
| `install.sh` | `curl -fsSL https://raw.githubusercontent.com/hearthroom/cli/main/install.sh \| sh`; detects OS/arch, verifies checksum, installs to `~/.local/bin` (or `$HEARTHROOM_INSTALL_DIR`) | ships |
| `install.ps1` | PowerShell equivalent; removes the download mark so SmartScreen does not prompt | ships |
| Build provenance | `actions/attest-build-provenance` on every release asset; verify with `gh attestation verify <file> --owner hearthroom` | ships |
| Homebrew tap | `hearthroom/homebrew-tap`, formula generated by GoReleaser | needs a cross-repo token as a repository secret; follow-up if absent |
| Scoop bucket | `hearthroom/scoop-bucket`, manifest generated by GoReleaser | same as above |
| winget | manifest PR to `microsoft/winget-pkgs` | follow-up |
| npm wrapper | `@hearthroom/cli` that downloads the platform binary | needs an npm account; follow-up |
| `hearthroom.club/install.sh` | Worker route that serves the script | follow-up in the site repository |

## Why unsigned binaries still install cleanly

- macOS Gatekeeper only quarantines files downloaded by a browser. `curl`,
  Homebrew and npm downloads carry no quarantine flag. Go's linker ad-hoc signs
  arm64 binaries, which Apple silicon requires. The README therefore documents
  script and package-manager installs and never asks users to download and
  double-click a binary.
- Windows SmartScreen also keys on the browser download mark; `install.ps1`
  clears it and Scoop/winget installs do not carry it. Hearthroom is an
  open-source project and can apply for free code signing through SignPath
  Foundation later; until then the build is reproducible and attested.
- Go binaries are built with `-trimpath`, without UPX, to reduce antivirus
  false positives.

## Self-update

`hearthroom upgrade` downloads the latest release for the current platform,
verifies the checksum, and replaces the running binary (rename-in-place; on
Windows it schedules the swap). Package-manager installs print the package
manager's upgrade command instead.

## Release procedure

1. `go test ./...` and the e2e suite against a local provider are green.
2. `goreleaser release --snapshot --clean` builds locally.
3. Tag `vX.Y.Z` (annotated), push the tag. The release workflow publishes
   assets, checksums and attestations.
4. Install from the published asset on macOS with `install.sh` and run
   `hearthroom version`; on Windows CI run the same from `install.ps1`.
5. Update the README install section only if the command changed.

## Acceptance

- A fresh macOS machine without Go: `curl … | sh` then `hearthroom version`.
- `gh attestation verify` passes for the downloaded archive.
